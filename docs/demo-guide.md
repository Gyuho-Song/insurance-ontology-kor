## 1. 시스템 개요

### 1.1 목적

보험 약관 PDF 문서를 **지식그래프(Knowledge Graph)** 로 구조화하고, **GraphRAG(Graph-based Retrieval-Augmented Generation)** 파이프라인을 통해 사용자의 자연어 질문에 **출처가 명확한 답변**을 생성하는 시스템입니다.

기존 RAG가 단순 텍스트 청크 검색에 의존하는 것과 달리, GraphRAG는 **엔티티 간 관계**(보장→면책→예외, 상품→규제 등)를 그래프로 표현하여 **논리적 추론 경로가 포함된 답변**을 생성합니다.

### 1.2 핵심 차별점

| 항목 | 기존 Naive RAG | GraphRAG (본 시스템) |
|------|---------------|---------------------|
| 데이터 구조 | 텍스트 청크 (비구조화) | 지식그래프 (구조화) |
| 검색 방식 | 벡터 유사도만 사용 | 하이브리드 검색 + 그래프 순회 |
| 답변 근거 | 유사 문장 나열 | 온톨로지 경로 기반 추론 |
| 출처 추적 | 문서 단위 | 조항·항 단위 (`[출처: 제X조Y항]`) |
| 규제 반영 | 없음 | 제약 경로 탐지 (금지/예외 자동 판별) |
| 검증 | 없음 | 위상적 충실도(Topological Faithfulness) 검증 |

### 1.3 데이터 규모

- **보험 상품**: 30개 (한화생명 종신·건강·암·상해·간병 등)
- **규제 조항**: 78개 (보험업법, 암관리법, 금융소비자보호법 등)
- **그래프 규모**: 1,889 노드 + 1,771 엣지
- **벡터 인덱스**: 1,952 문서 (1,024차원 임베딩)

## 3. 지식그래프 (Knowledge Graph)

### 3.1 온톨로지 스키마

보험 약관의 핵심 개념을 11종의 **노드 타입**과 10종의 **엣지 타입**으로 모델링합니다.

#### 노드 타입 (11종)

| 노드 타입 | 한글명 | 설명 | 노드 수 |
|-----------|--------|------|---------|
| **Policy** | 보험상품 | 보험 약관의 최상위 엔티티 (상품 단위) | 30 |
| **Coverage** | 보장항목 | 보험금 지급 조건·금액 | 433 |
| **Exclusion** | 면책사유 | 보험금 지급 제외 조건 | 224 |
| **Exception** | 예외조항 | 면책에 대한 단서·예외 | 97 |
| **Regulation** | 규제조항 | 관련 법률·감독 규정 | 219 |
| **Calculation** | 산출공식 | 보험료·환급금 계산 방법 | 280 |
| **Rider** | 특약 | 선택 가입 부가 보장 | 222 |
| **Eligibility** | 가입조건 | 연령·건강 상태 등 가입 자격 | 192 |
| **Surrender_Value** | 해약환급금 | 해지 시 환급 금액·비율 | 65 |
| **Premium_Discount** | 보험료할인 | 할인 조건·할인율 | 40 |
| **Dividend_Method** | 배당구조 | 유배당/무배당/상계 구조 | 32 |

#### 엣지 타입 (10종)

| 엣지 타입 | 방향 | 의미 |
|-----------|------|------|
| **HAS_COVERAGE** | Policy → Coverage | 상품이 이 보장을 포함함 |
| **EXCLUDED_IF** | Coverage → Exclusion | 이 조건에서 보장 면책됨 |
| **EXCEPTION_ALLOWED** | Exclusion → Exception | 면책의 단서/예외 존재 |
| **GOVERNED_BY** | Policy → Regulation | 이 규제가 적용됨 |
| **STRICTLY_PROHIBITED** | Regulation → 대상 | 규제에 의해 명시적 금지 |
| **EXCEPTIONALLY_ALLOWED** | Regulation → Exception | 규제의 예외 허용 |
| **HAS_DISCOUNT** | Policy → Premium_Discount | 보험료 할인 조건 |
| **SURRENDER_PAYS** | Policy → Surrender_Value | 해약환급금 지급 |
| **HAS_RIDER** | Policy → Rider | 부가 가능한 특약 |
| **WAIVES_PREMIUM** | Policy → Premium_Waiver | 납입면제 조건 |

### 3.2 그래프 구조 예시

```
Policy#시그니처H암보험
  ├── HAS_COVERAGE ──→ Coverage#암진단금
  │                      ├── EXCLUDED_IF ──→ Exclusion#고의사고
  │                      │                     └── EXCEPTION_ALLOWED ──→ Exception#2년경과예외
  │                      └── EXCLUDED_IF ──→ Exclusion#면책기간내진단
  ├── HAS_COVERAGE ──→ Coverage#수술급여금
  ├── HAS_RIDER ────→ Rider#입원일당특약
  ├── GOVERNED_BY ──→ Regulation#보험업법제95조
  │                     ├── STRICTLY_PROHIBITED ──→ ...
  │                     └── EXCEPTIONALLY_ALLOWED ──→ ...
  ├── SURRENDER_PAYS → Surrender_Value#1년_50%
  └── HAS_DISCOUNT ──→ Premium_Discount#건강체할인
```

이 구조 덕분에 **"자살하면 보험금을 못 받나요? 예외는 없나요?"** 같은 질문에 면책 경로(EXCLUDED_IF)를 타고 이동한 뒤, 예외 경로(EXCEPTION_ALLOWED)로 분기하여 **"2년 경과 후에는 예외적으로 지급 가능"** 같은 논리적 답변을 생성합니다.

### 3.3 제약 경로 (Constraint Edges)

그래프에는 두 가지 특수 엣지가 있습니다:

- **STRICTLY_PROHIBITED** (적색 경로): 규제에 의해 명시적으로 금지된 항목. 이 경로가 탐지되면 답변에서 "해당 항목은 규정에 의해 금지되어 있습니다"라고 명시합니다.
- **EXCEPTIONALLY_ALLOWED** (녹색 경로): 금지 규정의 예외 조항. 이 경로가 탐지되면 "다만, ~의 경우 예외적으로 허용됩니다"라고 보충합니다.

프론트엔드 그래프 시각화에서 이 경로들은 적색/녹색으로 강조됩니다.

## 4. 답변 생성 파이프라인 (7-Stage Pipeline)

사용자의 질문이 입력되면 7단계의 파이프라인을 거쳐 답변이 생성됩니다. 각 단계의 진행 상황은 프론트엔드의 **Pipeline Explorer**에서 실시간으로 확인할 수 있습니다.

### 전체 흐름도

```
사용자 질문 입력
     │
     ▼
┌─ Stage 1: Security ──────────────────────────────────┐
│  Gremlin 인젝션 + 프롬프트 인젝션 패턴 탐지          │
│  차단 시 → 즉시 안전 응답 반환 (파이프라인 미진입)    │
└──────────────────────────────────────────────────────┘
     │ pass
     ▼
┌─ Stage 2: Understand ────────────────────────────────┐
│  용어집 확장 (62개 동의어, 8개 약어)                  │
│  "면제" → ["면책", "면제사유", "면제조건"]             │
│  Titan Embed V2로 쿼리 임베딩 (1,024차원)             │
└──────────────────────────────────────────────────────┘
     │
     ▼
┌─ Stage 3: Classify ──────────────────────────────────┐
│  3-Tier 의도 분류:                                    │
│    Tier 1: 키워드 매칭 (188개 복합 키워드)            │
│    Tier 2: 시맨틱 라우터 (중심·예시 k-NN)             │
│    Tier 3: LLM 폴백 (Haiku)                          │
│  → 13개 의도 중 하나 + 엔티티(상품명 등) 추출         │
└──────────────────────────────────────────────────────┘
     │
     ▼
┌─ Stage 4: Search ────────────────────────────────────┐
│  3-Branch 하이브리드 벡터 검색:                       │
│    Branch A: 상품명 → 문서ID 기반 필터드 k-NN         │
│    Branch B: BM25 + k-NN → RRF(Reciprocal Rank       │
│              Fusion) 점수 합산                         │
│    Branch C: 순수 k-NN (벡터 유사도만)                │
│  → 진입 노드(entry nodes) Top-5 선정                  │
└──────────────────────────────────────────────────────┘
     │
     ▼
┌─ Stage 5: Traverse ──────────────────────────────────┐
│  의도 + 진입 노드 → Gremlin 템플릿 선택 (13종)       │
│  Neptune에서 그래프 순회 (1~4홉)                      │
│  서브그래프 추출 + 제약 경로 탐지                      │
│  노드 30개 기준 프루닝 (제약 경로 보호)               │
└──────────────────────────────────────────────────────┘
     │
     ▼
┌─ Stage 6: Generate ──────────────────────────────────┐
│  서브그래프 컨텍스트 + 프롬프트 규칙 → LLM 호출       │
│  Sonnet (복잡 쿼리) / Haiku (단순 쿼리)               │
│  스트리밍 응답 (토큰 단위 실시간 전송)                │
│  [출처: 제X조Y항] 형식으로 조항 인용                   │
└──────────────────────────────────────────────────────┘
     │
     ▼
┌─ Stage 7: Verify ────────────────────────────────────┐
│  위상적 충실도(Topological Faithfulness) 검증          │
│  답변의 주장 ↔ 서브그래프 노드/엣지 대조              │
│  점수 0.85 이상 → 통과 (high/medium/low 등급)        │
└──────────────────────────────────────────────────────┘
```

### 4.1 Stage 1: Security (보안 사전 필터)

질문이 파이프라인에 진입하기 전 두 가지 공격 패턴을 탐지합니다:

- **Gremlin 인젝션**: `.drop()`, `.addV()`, `g.V()` 등 그래프 DB 조작 시도
- **프롬프트 인젝션**: "ignore previous instructions", "역할 변경" 등 LLM 탈취 시도

차단 시 파이프라인에 진입하지 않고 즉시 안전 응답을 반환합니다 (응답 시간 약 29ms).

### 4.2 Stage 2: Understand (쿼리 이해)

**용어집 확장 (Glossary Expansion)**: 62개 동의어 매핑과 8개 약어 사전을 활용하여 검색 범위를 넓힙니다.

| 원본 용어 | 확장 결과 |
|-----------|-----------|
| 배당금 | 이익배당, 배당, 배당금액 |
| 면제 | 면책, 면제사유, 면제조건 |
| 해약 | 해지, 해약환급, 중도해약 |

확장된 쿼리를 Amazon Titan Embed V2 모델로 1,024차원 벡터로 변환합니다.

### 4.3 Stage 3: Classify (의도 분류)

3단계 캐스케이드 분류기로 사용자 의도를 13개 카테고리 중 하나로 분류합니다.

**13개 의도 타입:**

| 의도 | 설명 | 예시 질문 |
|------|------|-----------|
| COVERAGE_INQUIRY | 보장 조회 | "시그니처H암보험의 보장항목은?" |
| EXCLUSION_EXCEPTION | 면책/예외 | "자살하면 보험금을 못 받나요?" |
| SURRENDER_VALUE | 해약환급금 | "H종신보험 해지하면 환급금은?" |
| DIVIDEND_CHECK | 배당 확인 | "무배당 상품에 배당금이 있나요?" |
| DISCOUNT_ELIGIBILITY | 할인 조건 | "보험료 할인받을 수 있나요?" |
| REGULATION_INQUIRY | 규제 조회 | "적용되는 법률은?" |
| LOAN_INQUIRY | 대출 조회 | "보험계약대출 조건은?" |
| PREMIUM_WAIVER | 납입면제 | "납입면제 조건은?" |
| POLICY_COMPARISON | 상품 비교 | "H보장 vs H건강플러스 비교해주세요" |
| CALCULATION_INQUIRY | 산출 공식 | "보험료 계산 방법은?" |
| ELIGIBILITY_INQUIRY | 가입 조건 | "몇 살까지 가입 가능한가요?" |
| RIDER_INQUIRY | 특약 조회 | "가입 가능한 특약은?" |
| GENERAL_INQUIRY | 일반 질의 | 위에 해당하지 않는 기타 질문 |

**분류 정확도**: 99.0% (128개 평가 시나리오 기준)

### 4.4 Stage 4: Search (하이브리드 검색)

의도와 추출된 엔티티에 따라 3개 검색 브랜치 중 최적의 방식을 선택합니다:

| 브랜치 | 조건 | 방식 |
|--------|------|------|
| **A: 상품명 필터** | 질문에 상품명 포함 | 상품명 → Policy 노드 해석 → 해당 문서ID로 필터된 k-NN |
| **B: 토픽 검색** | 보장·면책·특약 등 주제 질문 | BM25(키워드) + k-NN(벡터) → RRF 점수 합산 |
| **C: 순수 k-NN** | 위에 해당하지 않을 때 | 벡터 유사도만 사용 |

**RRF (Reciprocal Rank Fusion)**: BM25와 k-NN의 순위를 결합하는 알고리즘으로, 두 검색 결과에 모두 등장하는 문서가 가장 높은 점수를 받습니다.

### 4.5 Stage 5: Traverse (그래프 순회)

의도에 맞는 **Gremlin 템플릿**(13종)을 선택하고, 진입 노드에서 시작하여 1~4홉의 그래프 순회를 실행합니다.

**주요 템플릿:**

| 템플릿 | 의도 | 순회 경로 |
|--------|------|-----------|
| coverage_lookup | 보장 조회 | Policy → Coverage → Exclusion → Exception |
| exclusion_exception_traverse | 면책/예외 | Coverage → Exclusion → Exception 집중 탐색 |
| dividend_eligibility_check | 배당 확인 | Policy → Dividend_Method + GOVERNED_BY |
| regulation_lookup | 규제 조회 | Policy → Regulation → 금지/예외 |
| comprehensive_lookup | 일반/폴백 | Policy에서 모든 방향 4홉 탐색 |

순회 결과로 **서브그래프**(관련 노드·엣지 집합)를 추출하고, 30개 노드 기준으로 프루닝합니다. 제약 경로(STRICTLY_PROHIBITED, EXCEPTIONALLY_ALLOWED) 노드는 프루닝에서 보호됩니다.

### 4.6 Stage 6: Generate (답변 생성)

서브그래프의 노드·엣지 정보를 LLM에 주입하여 답변을 생성합니다. 스트리밍 방식으로 토큰 단위 실시간 전송됩니다.

**모델 선택 기준:**
- 상품 비교, 복잡 경로(3홉 이상) → **Claude Sonnet 4.5** (고품질)
- 단순 조회, 짧은 질문 → **Claude Haiku 4.5** (빠른 응답)

**프롬프트 핵심 규칙:**
1. 반드시 `[출처: 제X조Y항]` 형식으로 인용
2. 추측·유추 절대 금지 ("일반적으로", "~일 가능성" 등 사용 불가)
3. STRICTLY_PROHIBITED 경로는 "규정에 의해 금지"로 명시
4. 데이터에 없는 정보는 "확인 필요"로 고지
5. 내부 용어(서브그래프, 노드 등) 사용 금지 — 자연어로만 답변

### 4.7 Stage 7: Verify (검증)

생성된 답변이 서브그래프의 실제 데이터와 일치하는지 **위상적 충실도(Topological Faithfulness)** 를 계산합니다.

```
충실도 = 답변에서 언급한 관계 중 서브그래프에 실존하는 관계 수
         ÷ 답변에서 언급한 총 관계 수
```

- **0.95 이상**: high (높은 신뢰도)
- **0.85~0.94**: medium (보통 신뢰도)
- **0.85 미만**: low (낮은 신뢰도, 검증 실패)
