## 2. 적용된 개선 사항

### Fix 1: Target Node Type 기반 폴백 로직

**문제**: 기존에는 서브그래프 노드 수가 4개 미만이면 무조건 comprehensive_lookup으로 폴백했습니다. surrender_value_lookup 같은 전문 템플릿은 자연스럽게 2~3개 노드만 반환하므로, 올바른 결과임에도 불필요하게 폴백되었습니다.

**해결**: 각 Gremlin 템플릿에 `target_node_types` 필드를 추가했습니다. 폴백 여부를 노드 개수가 아닌 **기대하는 노드 타입의 존재 여부**로 판단합니다.

```
surrender_value_lookup → target: ["Surrender_Value"]
eligibility_lookup     → target: ["Eligibility"]
rider_lookup           → target: ["Rider"]
coverage_lookup        → target: ["Coverage"]
...
```

**효과**: Template 차원 **+21.5pp** (52.2% → 73.7%). 특히 카테고리 C(해약환급금)가 1/8 → 6/8로 대폭 개선.

### Fix 2: 신규 Intent 및 전용 템플릿

**추가된 Intent**: `eligibility_inquiry`, `rider_inquiry`

**추가된 Gremlin 템플릿**:
- `eligibility_lookup`: `g.V('{policy_id}').outE('REQUIRES_ELIGIBILITY').inV()`
- `rider_lookup`: `g.V('{policy_id}').outE('HAS_RIDER').inV()`

**키워드 매핑**:
- 가입자격: "가입 조건", "가입 자격", "가입 가능", "가입연령", "심사", "건강진단" 등
- 특약: "특약들", "특약 목록", "선택특약", "부가특약", "특별약관" 등

**효과**: 카테고리 I(가입자격) **0/5 → 5/5 전체 통과**. 카테고리 H(특약) 3/6 → 4/6.

### Fix 3: 부정문 구별 및 의도 모호성 해소

**부정문 패턴 감지**: 정규식 기반 사전 필터로 "보험금을 못 받", "보장받지 못" 등 부정문 패턴 → `exclusion_exception`으로 직접 라우팅

```
"보험금[을를]?\s*못\s*받"  → exclusion_exception (0.95)
"보장받지\s*못"           → exclusion_exception (0.95)
"(지급|보장)\s*(안|못)"    → exclusion_exception (0.95)
```

**Disambiguation 규칙 추가**:
- "가입" + "특약" → `rider_inquiry` (eligibility와 충돌 방지)
- "환급금/보험료" + "계산식/산출 공식" → `calculation_inquiry`
- "비교/차이점" + 보험 도메인 용어 → `policy_comparison`
- "고지의무" + "위반/해지" → `exclusion_exception`

**효과**: Intent 차원 **+6.4pp** (79.5% → 85.9%). B04, B10, K02, K08, K10 등 의도 분류 개선.

### Fix 4: 답변 품질 및 프롬프트 보안

**시스템 프롬프트 추가 규칙**:
- **규제 환각 방지**: Regulation 노드가 없으면 일반 약관 조항을 규제로 해석하지 않음
- **용어 구분**: "면책"(보험금 지급 제한)과 "면제"(보험료 납입 면제)의 명확한 구분
- **입력 형식 무시**: JSON/XML/코드 출력 요청 → 일반 한국어 텍스트로 답변
- **개인 정보 안내**: 마이데이터 미연동 시 동의 안내 문구 제공

**LLM 전달 속성 확장**:
```python
_LLM_NODE_PROPS += {
    "formula_text", "formula_type", "applies_to", "variables",
    "benefit_name", "trigger_condition", "payment_amount",
    "min_age", "max_age", "gender", "health_condition",
    "rider_type", "rider_name", "rider_code",
}
```

**효과**: Answer 차원 **+5.4pp** (84.4% → 89.8%). 특히 F05, F06, F09, M06, O07, P01, P02, R07 등에서 답변 품질 개선.

## 7. 향후 개선 방향

### 우선순위 1: 데이터 보강 (영향: ~20건)

| 데이터 | 필요한 작업 | 영향 카테고리 |
|--------|-----------|-------------|
| `HAS_DISCOUNT` 엣지 + `Premium_Discount` 노드 | v2 그래프 데이터에서 할인 정보 추출/로딩 | E (6건) |
| `WAIVES_PREMIUM` 엣지 | v2 그래프 데이터에서 납입면제 관계 추출/로딩 | J (4건) |
| `CALCULATED_BY` 엣지 확장 | 더 많은 Coverage/Surrender → Calculation 연결 | G (4건) |

### 우선순위 2: Intent 분류 개선 (영향: ~14건)

- **의문형 부정문 감지**: "보험금이 나오나요?", "받을 수 있나요?" 등 → LLM 단계에서 보완
- **도메인 경계 Disambiguation 강화**: 규제/계산, 보장/계산 경계에 추가 규칙
- **Semantic Router 검토**: 키워드 기반 한계 극복을 위한 임베딩 기반 분류 고도화

### 우선순위 3: Vector 검색 정확도 (영향: ~9건)

- **상품명 유사도 개선**: "H종신보험" vs "상속H종신보험" vs "간편가입H종신보험" 구분
- **임베딩 모델 튜닝**: 상품명 가중치 강화

## 8. 결론

4가지 핵심 개선을 통해 **전체 시나리오 통과율이 39.1% → 64.1%로 25pp 향상**되었습니다. 특히 Template 라우팅 정확도가 52.2% → 73.7%로 가장 큰 개선을 보였으며, 이는 target_node_types 기반 폴백 로직이 핵심 기여 요인입니다.

잔여 실패의 38%는 **Neptune 데이터 부재**(HAS_DISCOUNT, WAIVES_PREMIUM, CALCULATED_BY 엣지)가 원인이므로, 데이터 보강이 다음 단계에서 가장 높은 ROI를 제공할 것으로 예상됩니다.
